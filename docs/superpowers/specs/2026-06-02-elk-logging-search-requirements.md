## 1. 项目背景

GoShopAdmin 是一个电商后台管理系统 + C 端商城的双端项目，当前已有 MySQL、Redis、RabbitMQ、Prometheus、Grafana 等基础设施。随着业务数据增长，以下问题日益突出：

1. **数据库查询压力**：商品、订单、用户等大表的模糊查询和复杂条件筛选直接命中 MySQL，导致慢查询
2. **日志分散**：两个 Go 后端的应用日志分别写入各自容器的 `./logs/` 目录，排查问题需要逐个容器查看
3. **容器日志丢失**：Docker 容器重启后 stdout 日志丢失，无法回溯历史错误
4. **缺乏可视化分析**：无法直观查看订单趋势、异常统计、用户行为等业务数据

## 2. 项目目标

运用 ELK（Elasticsearch + Logstash + Kibana）技术栈，实现以下两大核心能力：

### 2.1 数据搜索层

将商品、订单、用户、客户等业务数据同步到 Elasticsearch，提供高性能全文检索和复杂条件筛选，减轻 MySQL 查询压力。

### 2.2 日志分析层

集中收集 Go 应用日志和 Docker 容器日志，实现全文关键字查询、错误分析、运行状况监控。

## 3. 功能需求

### 3.1 业务数据搜索

| 编号 | 功能 | 描述 | 优先级 |
|------|------|------|--------|
| F-001 | 商品全文搜索 | 支持按商品名称、描述搜索，支持分类、价格区间、状态筛选 | 高 |
| F-002 | 订单全文搜索 | 支持按订单号、商品名搜索，支持状态、时间范围筛选 | 高 |
| F-003 | 用户搜索（后台） | 支持按用户名、邮箱搜索管理员用户 | 中 |
| F-004 | 客户搜索（C端） | 支持按用户名、手机号、邮箱搜索客户 | 中 |
| F-005 | 搜索结果高亮 | 搜索关键词在结果中高亮显示 | 中 |
| F-006 | 搜索建议 | 输入时提供搜索关键词补全建议 | 低 |

### 3.2 日志收集与分析

| 编号 | 功能 | 描述 | 优先级 |
|------|------|------|--------|
| F-007 | 应用日志收集 | 收集 backend 和 shop-backend 的 `utils.Logger` 输出的日志文件 | 高 |
| F-008 | 容器日志收集 | 收集所有 Docker 容器的 stdout/stderr 日志 | 高 |
| F-009 | 日志全文检索 | 支持按关键字、日志级别、服务名、时间范围搜索日志 | 高 |
| F-010 | 日志级别过滤 | 支持 INFO/WARN/ERROR 级别过滤 | 高 |
| F-011 | 错误日志告警 | ERROR 级别日志达到阈值时触发告警（Kibana 告警） | 低 |

### 3.3 可视化仪表盘

| 编号 | 功能 | 描述 | 优先级 |
|------|------|------|--------|
| F-012 | 订单统计仪表盘 | 订单趋势、状态分布、金额统计 | 高 |
| F-013 | 错误分析仪表盘 | 错误趋势、错误类型分布、慢请求统计 | 中 |
| F-014 | 容器监控仪表盘 | 各容器日志量、错误率对比 | 中 |
| F-015 | 搜索分析仪表盘 | 热门搜索词、搜索无结果率 | 低 |

### 3.4 前端搜索界面

| 编号 | 功能 | 描述 | 优先级 |
|------|------|------|--------|
| F-016 | 后台管理搜索 | 在 frontend 中集成商品/订单/用户搜索页面 | 高 |
| F-017 | C端商品搜索 | 在 shop-frontend 中集成商品搜索功能 | 高 |
| F-018 | C端订单查询 | 在 shop-frontend 中集成订单搜索查询 | 中 |

## 4. 非功能需求

| 编号 | 需求 | 指标 |
|------|------|------|
| NFR-001 | 搜索响应时间 | P95 < 200ms |
| NFR-002 | 数据同步延迟 | 业务数据从 MySQL 到 ES 延迟 < 30s |
| NFR-003 | 日志收集延迟 | 应用日志产生到可搜索 < 10s |
| NFR-004 | 日志保留期 | 7 天自动清理 |
| NFR-005 | 资源限制 | ES 2GB + Logstash 1GB + Kibana 512MB + Filebeat 256MB + search-service 256MB |
| NFR-006 | 高可用 | 开发环境单节点，生产环境需扩展为集群 |

## 5. 约束条件

| 编号 | 约束 | 说明 |
|------|------|------|
| C-001 | ELK 版本 | 使用 8.x 系列最新稳定版 |
| C-002 | 部署方式 | 全部通过 Docker 容器部署，加入现有 docker-compose.yml |
| C-003 | 网络环境 | 所有新服务加入现有 goshopadmin-network |
| C-004 | 数据同步方式 | 使用 Logstash JDBC 插件增量同步，基于 updated_at 字段 |
| C-005 | 搜索服务架构 | 独立 search-service，通过 HTTP REST 对外提供搜索 API |
| C-006 | 中文分词 | 使用 IK Analysis 插件支持中文全文搜索 |
| C-007 | 开发环境安全 | ES 关闭安全认证（xpack.security.enabled=false），生产环境必须开启 |

## 6. 现有系统影响分析

### 6.1 需要修改的现有模块

| 模块 | 修改内容 | 影响范围 |
|------|---------|---------|
| docker-compose.yml | 新增 5 个服务定义 | Docker 部署 |
| backend/utils/logger.go | 日志输出增加结构化 JSON 字段（service 字段） | 日志格式 |
| shop-backend/utils/logger.go | 日志输出增加结构化 JSON 字段（service 字段） | 日志格式 |
| frontend（后台管理） | 新增搜索页面和 API 调用 | 前端路由、页面 |
| shop-frontend（C端商城） | 新增商品搜索和订单查询功能 | 前端页面 |

### 6.2 新增模块

| 模块 | 位置 | 说明 |
|------|------|------|
| search-service | `d:\code\goshopadmin\search-service\` | 独立搜索服务，Go + Gin + ES Client |
| ELK 配置文件 | `d:\code\goshopadmin\docker\elk\` | ES/Logstash/Kibana/Filebeat 配置 |

## 7. 验收标准

1. Docker Compose 一键启动所有 ELK 服务，ES/Kibana 可正常访问
2. 商品、订单、用户、客户数据从 MySQL 自动同步到 ES，延迟 < 30s
3. 通过 search-service API 可对商品、订单、用户、客户进行全文搜索和条件筛选
4. backend 和 shop-backend 的应用日志自动收集到 ES，可通过 Kibana 搜索
5. Docker 容器日志自动收集到 ES，可通过 Kibana 搜索
6. Kibana 仪表盘展示订单统计和错误分析
7. 后台管理系统前端可使用搜索功能
8. C端商城前端可使用商品搜索和订单查询
9. 日志数据 7 天后自动清理
