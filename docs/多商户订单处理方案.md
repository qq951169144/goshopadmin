## 二、严重问题（必须修复）

### 问题1：订单创建时 merchant_id 硬编码为 1

- **位置**: `shop-backend/services/order_service.go:173`、`shop-backend/services/activity_order_service.go:164`
- **现状**:
  ```go
  MerchantID: 1, // TODO:默认商户ID,后续改成多商户
  ```
- **影响**: 所有订单都归属商户1，无法区分不同商户的订单
- **违反规则**: 规则3.2（禁止硬编码）、规则7（禁止TODO占位）
- **修改方案**: 从商品信息中动态获取 merchant_id，下单时按商户拆分订单

### 问题2：Product 模型缺少 MerchantID 字段

- **位置**: `shop-backend/models/product.go`
- **现状**: 模型中无 `MerchantID` 字段，但数据库 `products` 表有 `merchant_id INT NOT NULL`
- **影响**: 模型与数据库不一致；无法从商品推导所属商户，是问题1的根本原因
- **修改方案**: Product 模型增加 `MerchantID int` 字段，与数据库对齐

### 问题3：订单不支持多商户拆单

- **位置**: `shop-backend/models/order.go`、`shop-backend/services/order_service.go`
- **现状**: Order 只有一个 `MerchantID` 字段，`OrderItem` 无 `MerchantID`；下单逻辑将所有商品放入同一个订单
- **影响**: 不同商户的商品无法拆分为独立订单，无法实现多商户结算
- **修改方案**: 采用**按商户拆单**方案——购物车中不同商户的商品生成不同订单，每个订单独立结算

### 问题4：购物车未考虑多商户

- **位置**: `shop-backend/models/cart.go`、`shop-backend/services/cart_service.go`
- **现状**: `CartItem` 无 `MerchantID` 字段，购物车服务返回数据不按商户分组
- **影响**: 前端无法按商户分组展示购物车商品，下单时无法按商户拆单
- **修改方案**: CartItem 增加 `MerchantID` 字段（从商品自动获取），购物车服务按商户分组返回

### 问题5：数据库与模型严重不一致

- **现状**: 数据库 `init.sql` 中有 10+ 张表含 `merchant_id`，但 shop-backend 的 Go 模型中只有 Order 有此字段
- **涉及表**: products、product_skus、product_categories、activities、activity_products、redeem_codes 等
- **修改方案**: 逐一将模型与数据库对齐，至少 Product 必须增加 MerchantID

### 问题6：活动管理路由缺少权限中间件

- **位置**: `backend/routes/routes.go:229`
- **现状**: 活动路由组未使用 `PermissionMiddleware`，任何已认证用户可操作活动
- **修改方案**: 添加 `middleware.PermissionMiddleware("activity:manage")`

### 问题7：兑换码/搜索路由缺少权限中间件

- **位置**: `backend/routes/routes.go:246`、`backend/routes/routes.go:260`
- **修改方案**: 添加对应的权限中间件

## 五、核心修改方案——多商户订单处理

### 5.1 方案选型：按商户拆单

```
用户购物车商品：
  ├── 商户A: 商品1, 商品2  →  生成订单A (merchant_id=A)
  └── 商户B: 商品3         →  生成订单B (merchant_id=B)
```

**选择理由**：
- 每个商户独立订单，结算、发货、售后互不影响
- 符合主流电商平台（淘宝、京东）的设计
- 实现相对简单，改动可控

### 5.2 数据库变更

#### 5.2.1 cart_items 表增加 merchant_id

```sql
ALTER TABLE cart_items ADD COLUMN merchant_id INT NOT NULL DEFAULT 0 COMMENT '商户ID';
ALTER TABLE cart_items ADD INDEX idx_cart_items_merchant_id (merchant_id);
```

#### 5.2.2 order_items 表增加 merchant_id

```sql
ALTER TABLE order_items ADD COLUMN merchant_id INT NOT NULL DEFAULT 0 COMMENT '商户ID';
ALTER TABLE order_items ADD INDEX idx_order_items_merchant_id (merchant_id);
```

> 注：products 表和 orders 表已有 merchant_id 字段，无需修改。

### 5.4 shop-backend 服务层改造

#### 5.4.1 购物车服务 (cart_service.go)

- `AddToCart`: 加入购物车时，从商品信息获取 merchant_id 并存入 CartItem
- `GetCart`: 返回数据按商户分组，结构调整为：

```go
// CartGroupInfo 按商户分组的购物车信息
type CartGroupInfo struct {
    MerchantID   int          `json:"merchant_id"`
    MerchantName string       `json:"merchant_name"`
    Items        []CartItemInfo `json:"items"`
    TotalAmount  decimal.Decimal `json:"total_amount"`
}

// CartInfo 购物车信息（多商户分组）
type CartInfo struct {
    Groups       []CartGroupInfo `json:"groups"`
    TotalAmount  decimal.Decimal `json:"total_amount"`
    TotalCount   int             `json:"total_count"`
}
```

#### 5.4.2 订单服务 (order_service.go)

- `CreateOrder`: 核心改造——按商户拆分订单

```go
// CreateOrderResult 创建订单结果
type CreateOrderResult struct {
    Orders []OrderInfo `json:"orders"` // 多个订单
}

// CreateOrder 创建订单（按商户拆单）
func (s *OrderService) CreateOrder(req *CreateOrderRequest) (*CreateOrderResult, error) {
    // 1. 查询购物车商品，获取每个商品的 merchant_id
    // 2. 按 merchant_id 分组
    // 3. 每组生成一个独立订单
    // 4. 返回多个订单信息
}
```

关键逻辑：
1. 遍历购物车商品项，从 Product 查询 merchant_id
2. 按 merchant_id 分组为 map[merchantID][]orderItem
3. 每组创建一个 Order（含对应的 OrderItem）
4. 每个订单独立计算金额、独立生成订单号
5. 清空已下单的购物车商品
6. 返回所有订单信息

#### 5.4.3 活动订单服务 (activity_order_service.go)

- 从活动信息中获取 merchant_id 替代硬编码

## 十、风险与注意事项

1. **数据迁移**: 新增 merchant_id 字段需设置默认值，已有数据需通过 UPDATE 语句从 products 表回填
2. **购物车兼容**: 加入购物车时需确保商品有 merchant_id，历史购物车数据需迁移
3. **拆单后支付**: 每个订单独立支付，需确认支付流程是否支持批量支付
4. **活动订单**: 活动商品通常只属于一个商户，但仍需从活动信息获取 merchant_id
5. **前端交互**: 拆单后用户可能部分订单支付、部分未支付，需明确订单状态展示逻辑
